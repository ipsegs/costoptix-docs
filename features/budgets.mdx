## Overview

Open **Budgets** in the navigation. It has two parts:

- **Budgets** track spend over a month, quarter or year, warn you before you go over, and say which resources are pushing you there.
- **Daily limits** alert you when a single settled day goes over an amount you set.

Only organisation admins can create or change budgets and limits.

<Info>
  Budget and limit alerts are sent by webhook. Connect Slack, Teams, Discord or your own endpoint in **Settings → Webhooks** first. See [Webhooks](/features/webhooks).
</Info>

## Creating a budget

Pick a scope, then fill in the details.

| Scope | What it tracks |
|---|---|
| **Account** | One cloud account, one Kubernetes cluster, one host, or **All Accounts** for the whole organisation |
| **Tag** | Cloud spend matching one or more tag values, in one account or across all of them |
| **Team** | A team's spend across Kubernetes, hosts and the cloud spend it owns (see [Ownership](/features/ownership)) |
| **AI / LLM** | What your AI coding tool plans charge, in USD |

| Field | Description |
|---|---|
| Name | A label you will recognise |
| Amount | The limit for the period |
| Period | Monthly, quarterly or yearly |
| Warning threshold | Percentage that triggers a warning (default 80%) |
| Critical threshold | Percentage that triggers a critical alert (default 95%) |

When you pick a specific account, CostOptix suggests an amount based on how that account's spend usually moves, not a round number.

<Note>
  **All Accounts** covers cloud accounts and hosts. Clusters already inside a connected cloud bill are not added again. Kubernetes clusters on their own are tracked with a per-cluster budget.
</Note>

### Tag budgets

Add one or more tag rules. A rule is a key, an operator and a value:

```
team = payments
env in [production, staging]
```

`=` matches one value. `in` matches any value in a comma-separated list. Multiple rules are combined with AND. Tag budgets are cloud only, because clusters and hosts carry no cloud tags.

## Alerts

| State | Default trigger | Webhook event |
|---|---|---|
| Warning | 80% of the budget | `budget.warning` |
| Critical | 95% of the budget | `budget.critical` |
| Exceeded | 100% of the budget | `budget.exceeded` |

Each alert includes current spend, predicted spend, days remaining and, when one is projected, the date the budget is expected to be breached.

## Forecasts and pressure

Each budget shows:

- **Predicted spend.** A worst-case estimate for the end of the period, built from up to 11 months of history. With little history it falls back to a straight-line projection.
- **Projected breach date.** When spend is on course to pass the budget.
- **What is pushing it.** When a budget comes under pressure, it lists the resources responsible. Each one shows recent daily spend against its own baseline and is flagged as a spike, a new resource or steady growth.

The same pressure strip appears on the Kubernetes, Hosts and LLM Usage pages, so you see a budget at risk where you are working.

## Daily limits

A daily limit alerts you when one settled day goes over the amount you set. Use it to catch a runaway day without waiting for the monthly budget.

1. In **Budgets**, find **Daily limits** and click **Add limit**.
2. Pick a source: **All accounts**, one cloud account, one cluster or one host.
3. Enter the daily amount.

Cloud providers post costs 24 to 72 hours late, so limits are checked on the last few settled days, and each day alerts at most once per limit. Alerts go to webhooks subscribed to **Daily Spend Limit Exceeded** (`spend.daily_exceeded`) and include the top services that day.

---

## Suggestions

You do not have to work out every amount yourself. Each night CostOptix looks for sources that have no budget or no daily limit and suggests one. Suggestions appear behind a button in the header.

- **Create budget** or **Set limit** accepts it in one click.
- **Adjust** opens the form prefilled, so you can change the amount first.
- **Not now** hides it for a week.

If no webhook is subscribed to budget alerts, the suggestion reminds you to connect one, since alerts only go out by webhook.

---

## Editing and deleting

Open a budget and click **Edit** to change any field. Changes apply immediately. Deleting a budget or limit is permanent.
