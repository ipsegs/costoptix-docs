## Overview

Webhooks are how CostOptix tells you something happened. Every alert in the product (budgets, daily limits, anomalies, runaway AI sessions, expiring credentials) goes out by webhook. Webhooks are available on every plan.

**Supported destinations:**
- Slack
- Microsoft Teams (Workflow, recommended)
- Microsoft Teams (legacy connector, deprecated by Microsoft)
- Discord
- Any HTTPS endpoint (custom)

---

## Setting up a webhook

1. Go to **Settings → Webhooks** and click **Add Webhook**.
2. Pick the destination and paste its webhook URL.
3. Choose the events to subscribe to.
4. Optionally add a secret so you can verify deliveries.
5. Save, then click **Test** to send a test message.

<Tabs>
  <Tab title="Slack">
    1. Go to [api.slack.com/apps](https://api.slack.com/apps) and create an app.
    2. Turn on **Incoming Webhooks**.
    3. Click **Add New Webhook to Workspace** and pick a channel.
    4. Copy the URL (`https://hooks.slack.com/services/...`).
  </Tab>
  <Tab title="Teams (Workflow)">
    1. In Teams, open the channel for alerts.
    2. Click **···** then **Workflows**.
    3. Choose **Post to a channel when a webhook request is received**.
    4. Finish the wizard and copy the workflow URL.
  </Tab>
  <Tab title="Discord">
    1. Open the channel settings.
    2. Go to **Integrations → Webhooks → New Webhook**.
    3. Copy the URL (`https://discord.com/api/webhooks/...`).
  </Tab>
  <Tab title="Custom">
    Any HTTPS endpoint that accepts a `POST` with a JSON body. See [Payload format](#payload-format).
  </Tab>
</Tabs>

## Events

| Event | Name in the app | Fires when |
|---|---|---|
| `budget.warning` | Budget Warning | A budget crosses its warning threshold |
| `budget.critical` | Budget Critical | A budget crosses its critical threshold |
| `budget.exceeded` | Budget Exceeded | A budget passes its limit for the period |
| `spend.daily_exceeded` | Daily Spend Limit Exceeded | A settled day's spend passes a daily limit |
| `anomaly.detected` | Cost Anomaly Detected | An [important anomaly](/features/anomaly-detection#important-anomalies) is found |
| `llm.runaway_session` | Runaway AI Session | A coding-agent session spends far above your normal hourly rate |
| `unit_cost.changed` | Unit Cost Changed | A metric's cost per unit jumped or went above its target (Professional and above). Revenue metrics never send it. |
| `credential.expiring` | Credential Expiring Soon | Cloud account credentials expire within 30 days |
| `credential.expired` | Credential Expired | Credentials expired and cost sync has stopped |
| `credential.rotated` | Credential Rotated | Cloud account credentials were rotated |
| `report.weekly` | Weekly Cost Report | Spend digest for the previous week (Professional and above) |
| `report.monthly` | Monthly Cost Report | Spend digest for the previous month (Professional and above) |

## Payload format

Slack, Teams and Discord get a formatted message. Custom endpoints get raw JSON, sent as `POST` with `Content-Type: application/json`. Every payload has the same envelope:

```json
{
  "event": "budget.warning",
  "timestamp": "2026-10-01T14:32:00Z",
  "organization_id": "org_abc123",
  "data": { }
}
```

<AccordionGroup>

    ```json
    "data": {
      "budget_id": "bud_xyz789",
      "budget_name": "Production AWS",
      "budget_amount": 5000.00,
      "current_spend": 4100.00,
      "predicted_spend": 5800.00,

      "threshold": "warning",

      "breached_on": "2026-10-24",
      "excluded_currencies": []

    ```
    `breached_on` is the projected breach date, or empty when none is projected. `excluded_currencies` lists plan currencies left out of an AI / LLM budget.
  </Accordion>
  <Accordion title="Unit cost (unit_cost.changed)">
    ```json
    "data": {
      "metric_id": "5f0c2a9e-1b7d-4c1e-9a43-2d6b8e0f7a11",
      "metric_name": "Orders",
      "unit": "order",
      "scope": "org",
      "reason": "spike",
      "period": "2026-10-04",
      "unit_cost": 0.42,

      "rise_percent": 35,
      "cost": 2100.00,
      "metric_value": 5000,
      "currency": "USD"
    }
    ```
    `reason` is `spike` when a daily cost per unit jumps above its recent history, with `expected` and `rise_percent`. It is `above_target` when a month passes the metric's target, with `target` and `final` (whether the month's costs have settled) instead. Team metrics add `team_id` and `team_name`.
  </Accordion>
  <Accordion title="Anomaly (anomaly.detected)">

## Verifying deliveries

If you set a secret, every delivery carries an `X-Webhook-Signature` header: `sha256=` followed by the HMAC-SHA256 of the raw request body, using your secret as the key. Check it before trusting the payload:

```javascript
const crypto = require('crypto');

function verifySignature(rawBody, signature, secret) {
  const expected = 'sha256=' + crypto
    .createHmac('sha256', secret)
    .update(rawBody)
    .digest('hex');
  return signature.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expected));
}
```

## Delivery and retries

- Each delivery is tried up to **3 times**, waiting longer between attempts.
- A `4xx` response is not retried, since it means the request itself was rejected.
- Payloads are capped at 100 KB.
- The last 50 deliveries for each webhook, with status codes and responses, are under **History** in **Settings → Webhooks**.
