## Supported sources

| Source | How it connects | Billing lag | Guide |
|---|---|---|---|
| Microsoft Azure | Service principal or managed identity | Up to 5 days | [Azure](/providers/azure) |
| Amazon Web Services | Access keys or IAM role | 1 to 3 days | [AWS](/providers/aws) |
| Google Cloud | Service account reading the BigQuery billing export | 1 to 3 days | [GCP](/providers/gcp) |
| Kubernetes | Agent inside the cluster | None, accrues live | [Kubernetes](/providers/kubernetes) |
| Linux machines | Host agent running under systemd | None, accrues live | [Hosts](/providers/hosts) |
| AI coding tools | OpenTelemetry sent by the tool | None | [AI coding tools](/providers/llm) |

New sources are added regularly. If you need one that is not listed, contact [support@costoptix.com](mailto:support@costoptix.com).

## Two ways to connect

**Cloud accounts use read-only credentials.** An organisation admin opens **Organization Admin → Accounts → Add Account** (from the profile menu), picks the provider and pastes the credentials. CostOptix checks them and starts the first sync. Each account is one Azure subscription, one AWS account or one GCP project.

**Everything else uses a small agent or telemetry.** Kubernetes clusters, Linux machines and AI coding tools push data to CostOptix with a key that can only send that one kind of data. Nothing needs to reach into your network. Each has guided setup on its own page in the app: **Kubernetes**, **Hosts** and **LLM Usage**.

<Info>
  Members who are not admins see connected accounts in read-only mode. Ask an admin to add or change a source.
</Info>

## How sources add up

Some spend shows up in two places. A Kubernetes node running in AWS is on your AWS bill and is also measured by the cluster agent. CostOptix counts it once:

| Source | Counted |
|---|---|
| Cloud bills | Always added to the total |
| Clusters and machines on a **connected** cloud account | Shown as a breakdown of that cloud bill, not added again |
| Clusters and machines anywhere else (bare metal, on-prem, another provider) | Added to the total |
| AI coding tool plans | Added to the total |

To make this work, tell CostOptix where a cluster or machine is billed:

- **Kubernetes:** set a billing link on the cluster page. See [Invoice reconciliation](/providers/kubernetes#invoice-reconciliation).
- **Hosts:** set **Billed through** in the machine's cost settings. See [Hosts](/providers/hosts#tell-costoptix-what-it-costs).

A cluster without a billing link is always counted on its own, with a reminder to link it if its nodes are in a connected account.

## Limits

How many cloud accounts, Kubernetes nodes, hosts and AI tool users you can connect depends on your plan. You can go beyond it with add-ons. See [Subscription Tiers](/getting-started/subscription-tiers).

---

## Security

Every connection is read-only. CostOptix never creates, changes or deletes anything in your accounts, clusters or machines, and never buys anything for you. Credentials are encrypted at rest with AES-256-GCM. See [Security](/security).

---

## Removing a source

- **Cloud account:** open **Organization Admin → Accounts**, find the account and delete it. Its stored credentials and cost data are removed. Your cloud account is not touched.
- **Kubernetes cluster:** uninstall the agent, then delete the cluster in CostOptix. See [Removing a cluster](/providers/kubernetes#removing-a-cluster).
- **Linux machine:** stop and remove the agent service, then delete the host in CostOptix. See [Removing a host](/providers/hosts#removing-a-host).
- **AI coding tools:** remove the telemetry settings from the tool and revoke the telemetry key in **Settings → API Keys**.
