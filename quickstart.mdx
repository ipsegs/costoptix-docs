## Step 1: Create your account

Go to [costoptix.com/signup](https://costoptix.com/signup) and sign up. Verify your email with the link we send, and you land in your organisation.

<Note>
  Disposable email addresses are not accepted. Use a permanent work or personal address.
</Note>

---

## Step 2: Connect a source

Pick whatever you want to track first. You can add the rest later.

<Tabs>
  <Tab title="Azure">
    Open **Organization Admin → Accounts → Add Account** (from your profile menu) and choose Microsoft Azure. You need a service principal with **Reader** and **Cost Management Reader** on the subscription:

    - Tenant ID
    - Client ID
    - Client secret
    - Subscription ID

    Step-by-step commands are in the [Azure guide](/providers/azure).
  </Tab>
  <Tab title="AWS">
    Open **Organization Admin → Accounts → Add Account** (from your profile menu) and choose Amazon Web Services. You need an IAM user or role with read-only Cost Explorer access:

    - Access key ID and secret access key, **or** a role ARN

    The minimum IAM policy is in the [AWS guide](/providers/aws).
  </Tab>
  <Tab title="GCP">
    Open **Organization Admin → Accounts → Add Account** (from your profile menu) and choose Google Cloud. You need a **Detailed usage cost** BigQuery billing export and a service account that can read it:

    - Project ID
    - Service account JSON key

    See the [GCP guide](/providers/gcp).
  </Tab>
  <Tab title="Kubernetes">
    Open **Kubernetes** and follow the three guided steps: name the cluster, create an agent key, and run the installer command. The key and command are filled in for you.

    You need `kubectl` access to the cluster. `metrics-server` is recommended for usage and rightsizing data.

    See the [Kubernetes guide](/providers/kubernetes).
  </Tab>
  <Tab title="Linux machine">
    Open **Hosts** and follow the guided steps: name the machine, tell us what it costs, create an agent key, and run the installer over SSH.

    The machine needs systemd and cgroup v2, which covers Ubuntu 22.04+, Debian 11+ and RHEL, Rocky or Alma 9+.

    See the [Hosts guide](/providers/hosts).
  </Tab>
  <Tab title="AI coding tools">
    Open **LLM Usage** and click **Connect a tool**. Create a telemetry key, then paste the generated settings into Claude Code or Gemini CLI.

    See the [AI coding tools guide](/providers/llm).
  </Tab>
</Tabs>

## Step 3: Wait for the first data

| Source | First data | Why it can lag |
|---|---|---|
| Azure | A few minutes after connecting | Azure posts costs up to 5 days late |
| AWS | A few minutes after connecting | AWS posts costs 1 to 3 days late |
| GCP | A few minutes after connecting | The billing export updates 1 to 3 days late |
| Kubernetes | After the agent's first report | No billing lag, cost accrues live |
| Linux machine | After one collection interval (5 minutes by default) | No billing lag, cost accrues live |
| AI coding tools | About a minute after the first prompt | No billing lag |

<Info>
  Cloud billing lag comes from the provider. Today's cloud cost is never final today.
</Info>

## Step 4: Look around

- **Overview** shows every source in one total, how it compares with last month, and who owns what. Organisations with two or more sources land here after sign-in.
- **Dashboard**, **Daily Spend** and **Cost Explorer** go deep on one cloud account.
- **Kubernetes**, **Hosts** and **LLM Usage** each have their own page with costs, waste and anomalies.

---

## Step 5: Set up alerts

Alerts are sent by webhook, so connect one first:

1. Go to **Settings → Webhooks** and add Slack, Microsoft Teams, Discord or your own endpoint. See [Webhooks](/features/webhooks).
2. Go to **Budgets** and create a monthly budget, or add a daily spend limit. See [Budgets](/features/budgets).

<Tip>
  You do not have to work out the amounts. CostOptix suggests a budget or daily limit for each source that has none, and you can accept it in one click from the suggestions button in the header.
</Tip>
